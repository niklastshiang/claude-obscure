# README template

A starting point, based on the README Stickler settled on, with Install moved up so a reader gets
to "what is it, does it fit me, how do I install it" quickly. Before using it, compare it with the
READMEs of successful projects of the same kind (see SKILL.md, *README*) and adapt: drop what this
project does not need, and move up what its readers look for first. *(optional)* marks sections
that only some projects need.

Separate sections with `---`. Keep each one short and link to `docs/` for depth.

1. **Title and one-line tagline** (centred): what it is, in one sentence a stranger understands.
2. **Fact badges** (one row): licence (linked), supported runtime versions, test coverage,
   version, and at most one distinctive fact. Rendered by a script and committed as SVGs, so the
   README does not depend on a badge service.
3. **What is this**: what it does, for whom, and the promise it keeps.
4. **Screenshots or a short demo** of the real product, with captions; free-licensed sample
   content only, credited.
5. **Install**: the shortest path for users (packages, one command), and how to remove it again.
6. **Usage**: the first thing to do after installing, in a few lines.
7. **Why** *(optional)*: the motivation in a few sentences.
8. **Warnings and limits**: how good it really is, third-party licences that restrict use, anything
   a user must know before relying on it.
9. **Results** *(optional, for projects that measure quality)*: key numbers in a small table, the
   takeaways as bullets, a link to the full report.
10. **How it works**: one diagram, a few bullets on the architecture.
11. **Roadmap**: done per release (checklists), then what comes next.
12. **Build it yourself**: prerequisites per platform, clone, install dependencies, enable the
    pre-commit hook, first command, check command; links to the developer docs.
13. **Key figures** *(optional)*: a block generated by a script (tests, coverage, minimum,
    decisions recorded, version, status).
14. **Origin** *(optional, if the owner chose to publish how it was made)*: badges "built with
    <agent>", "code: 100% AI", "decisions: 100% human", "AI cost", "tokens"; a paragraph on the
    owner's role; the guardrails as bullets (spec first, tests first with a coverage floor, a guard
    against weakened checks, measure don't assert); a table of AI usage and cost at API prices,
    regenerated each release, with the method and its caveats.
15. **Repository layout**: an annotated tree of the top folders.
16. **Licence**: the code's licence (and its history if it changed), third-party licences, data.
17. **Contributing**: one line linking CONTRIBUTING.md (what kind of contributions are taken).
